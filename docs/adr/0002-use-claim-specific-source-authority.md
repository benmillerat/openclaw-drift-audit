# Use claim-specific source authority

The auditor does not use one universal source ranking. Active binaries and build metadata establish installed identity; exact-version schemas and validators establish accepted constraints; exact-release resolvers establish effective defaults; versioned component-owner documentation establishes recommendations; and stable release plus compatibility metadata establishes an Upgrade Contract. Tests and examples are corroborating evidence, while community material is only a discovery lead. Official GitHub issues, pull requests, and maintainer comments are admitted as tiered evidence: only a change whose commit belongs to the relevant release line is Shipped Evidence; unreleased merges, open or ambiguously closed issues, and comments remain Candidate Evidence for risk or rationale. Every claim retains Evidence Provenance, and contradictory authoritative sources produce a visible Baseline Conflict rather than a silently selected value or compliance verdict.
